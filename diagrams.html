⏱ Sequence Diagram 1 — Login & JWT Auth Flow

Shows the full JWT authentication handshake from login to protected resource access.

sequenceDiagram actor User participant Frontend participant AuthController participant AuthService participant AuthManager as AuthenticationManager participant JwtService participant DB as PostgreSQL User->>Frontend: Enter email + password Frontend->>AuthController: POST /api/v1/auth/login AuthController->>AuthService: login(request) AuthService->>AuthManager: authenticate(email, password) AuthManager->>DB: SELECT * FROM users WHERE email=? DB-->>AuthManager: User record AuthManager-->>AuthService: Authentication OK AuthService->>DB: findByEmail(email) DB-->>AuthService: User entity AuthService->>JwtService: generateToken(user) JwtService-->>AuthService: JWT (with role claim) AuthService-->>AuthController: AuthResponse {token, name, role} AuthController-->>Frontend: 200 OK {token, userId, name, role} Frontend->>Frontend: Store token in AuthContext Note over Frontend,DB: Subsequent Requests User->>Frontend: Navigate to protected page Frontend->>AuthController: GET /api/v1/... + Bearer token AuthController->>AuthController: JwtAuthenticationFilter intercepts AuthController->>JwtService: extractUsername(token) JwtService-->>AuthController: email AuthController->>DB: loadUserByUsername(email) DB-->>AuthController: UserDetails AuthController->>JwtService: isTokenValid(token, userDetails) JwtService-->>AuthController: true AuthController->>AuthController: Set SecurityContextHolder AuthController-->>Frontend: 200 OK + protected data

⏱ Sequence Diagram 2 — Attendance Submission & Absence Detection

The core business flow: submitting attendance, detecting consecutive absences, and alerting admins.

sequenceDiagram actor Facilitator participant Frontend participant AttendanceController participant AttendanceService participant AbsenceDetection as AbsenceDetectionService participant SessionRepo participant RecordRepo participant NotificationService participant DB as PostgreSQL participant Email as Gmail SMTP Facilitator->>Frontend: Create session (date, time, period) Frontend->>AttendanceController: POST /api/v1/modules/{id}/sessions AttendanceController->>AttendanceService: createSession(moduleId, request, user) AttendanceService->>DB: save AttendanceSession DB-->>AttendanceService: Session saved AttendanceService-->>Frontend: 201 Created — Session Facilitator->>Frontend: Submit attendance list [studentId, status] Frontend->>AttendanceController: POST /api/v1/sessions/{id}/records AttendanceController->>AttendanceService: submitRecords(sessionId, records) loop For each student record AttendanceService->>RecordRepo: findBySessionIdAndStudentId RecordRepo->>DB: SELECT ... DB-->>RecordRepo: existing or null AttendanceService->>RecordRepo: save(record) RecordRepo->>DB: INSERT / UPDATE attendance_records end loop For each student record AttendanceService->>AbsenceDetection: checkAndFlag(studentId, moduleId) AbsenceDetection->>SessionRepo: findTop2ByModuleId (last 2 sessions) SessionRepo->>DB: SELECT ... ORDER BY date DESC LIMIT 2 DB-->>AbsenceDetection: [session1, session2] AbsenceDetection->>RecordRepo: findByStudentIdAndSessionIdIn DB-->>AbsenceDetection: [record1, record2] alt Both records = ABSENT AbsenceDetection->>RecordRepo: set consecutiveAbsentFlag = true RecordRepo->>DB: UPDATE attendance_records AbsenceDetection->>NotificationService: notifyAdmins(studentId, moduleId) [ASYNC] NotificationService->>DB: findAllByRole(ADMIN) DB-->>NotificationService: admin users loop For each Admin NotificationService->>DB: INSERT INTO notifications NotificationService->>Email: send alert email Email-->>NotificationService: sent end else Not consecutive AbsenceDetection-->>AttendanceService: no flag end end AttendanceService-->>Frontend: 200 OK — records saved Frontend-->>Facilitator: ✅ Attendance submitted
